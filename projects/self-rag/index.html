Self-RAG: Grounded Answers

A LangGraph pipeline that decides when to retrieve, checks grounding, and bounds its revision and query-rewrite loops.

LangGraph · LangChain · FAISS · Pydantic · Gradio

The problem

Retrieving a document does not guarantee a supported or useful answer. A system also needs to decide whether retrieval is necessary and recognize when the source does not contain an answer.

System architecture

The public implementation uses structured LLM judgments to route retrieval, filter relevant chunks, check support, and assess usefulness. Unsupported answers are revised into direct quotes; unhelpful answers can trigger a rewritten retrieval query.

Implementation

  • Uses typed Pydantic outputs for graph routing rather than parsing free-form model text.
  • Maintains separate retry budgets, documented as at most three answer revisions per retrieval and three retrieval-query rewrites.
  • Builds a per-session FAISS index for uploaded documents, with configurable model and embedding providers.
  • Includes offline graph tests with a scripted fake LLM so control-flow behavior can be tested without an API key.

Technical challenges

A grounded answer can still be off-topic. Support checking and usefulness checking are separate gates, and missing-answer paths can consume more model calls than straightforward questions.

Decisions & trade-offs

The README explicitly documents the cost of repeated judging, less natural quote-only revisions, and the limitations of using the same model as writer and judge. Retry budgets prevent an unbounded loop; they do not guarantee answer correctness.

Evaluation & outcomes

The repository documents working retrieval, direct-answer, revision, query-rewrite, and no-answer paths. These examples demonstrate control flow; no independently measured accuracy or production-scale latency result is claimed.

Evidence

The public README, graph implementation, and offline tests support this case study. The repository does not currently provide a deployed-demo URL.
