Engineering Drawing OCR Pipeline

From small, rotated labels in P&ID drawings to text that can be inspected and edited in a PDF workflow.

Python · PaddleOCR · PaddleOCR-VL · FastAPI

The problem

Engineering drawings are not ordinary text documents. Small labels, rotated text, and complex geometry make extraction difficult; plain text output also loses the spatial context required for editing.

System architecture

I built a document-editing workflow around PaddleOCR and PaddleOCR-VL, with Python and FastAPI connecting extraction to application APIs. The workflow retains text and bounding boxes so extracted content can be reviewed and edited in context.

Implementation

  • Used image preprocessing and OCR benchmarking to work on small and rotated labels.
  • Applied confidence analysis and bounding-box-based editing rather than treating extracted text as the final product.
  • Integrated the extraction workflow with backend application APIs using FastAPI.

Technical challenges

Text correctness and geometric alignment are separate problems. An OCR output can read correctly but still be unusable for editing if its position or orientation is wrong.

Decisions & trade-offs

The engineering focus was inspectable output: preserve geometry and support review instead of presenting every OCR prediction as equally reliable. Comparative model benchmarks and coordinate round-trip errors are not published here.

Evaluation & outcomes

Delivered an editable-document workflow around engineering drawings. A public accuracy benchmark, representative test set, and measured end-to-end latency have not been provided, so this case study does not claim numerical performance.
