Evaluation / Personal project

RAG Evaluation Framework

An end-to-end PDF retrieval workflow with quality checks and structured experiment logs, beyond a plausible-looking answer.

LangChain · LangGraph · DeepEval · FAISS

The problem

RAG quality depends on both the retrieved context and the generated answer. Looking at a few good examples does not reveal which stage is failing.

System architecture

I built a workflow for PDF ingestion, vector embeddings, semantic retrieval, and context-aware generation. DeepEval checks answer relevancy, faithfulness, contextual relevancy, and correctness; JSONL logs make runs and retrieval strategies comparable.

Implementation

  • Connected document ingestion and semantic retrieval to a LangGraph generation workflow.
  • Separated context-oriented and answer-oriented evaluation criteria.
  • Recorded structured experiment outputs to compare strategies and inspect retrieval or generation bottlenecks.

Technical challenges

A change can improve retrieval while leaving answer quality unchanged. Context relevance, answer support, and correctness need separate observations.

Decisions & trade-offs

Multiple quality dimensions provide a more useful picture than a single score, but evaluation thresholds, judge configuration, and test-set composition affect the interpretation. Those configuration details are not yet published here.

Evaluation & outcomes

Built an automated evaluation and experiment-tracking workflow across four quality dimensions. No aggregate score or improvement percentage is shown because a reproducible benchmark has not been supplied.
